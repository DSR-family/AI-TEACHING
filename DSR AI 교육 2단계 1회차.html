프로그램과 개발 흐름 이해하기

SECTION 01

프로그램이란 무엇인가

프로그램은 사용자의 입력을 받아, 정해진 방식으로 처리하고, 그 결과를 출력물로 보여주는 것입니다.

예를 들어 엑셀 파일을 입력값으로 하여 정해진 규칙에 따라 데이터를 정리하고, 최종 결과를 PDF 파일로 생성하는 과정도 하나의 프로그램입니다.

1
입력 (Input)
사용자가 넣는 자료. 엑셀 파일, 텍스트, 클릭 같은 행동 자체도 입력이 될 수 있습니다.
↓
2
처리 (Process)
정해진 규칙과 순서에 따라 입력을 계산하거나 가공하는 단계. 프로그램의 핵심 로직이 여기 있습니다.
↓
3
출력 (Output)
처리 결과를 사람이 확인할 수 있는 형태로 보여주는 단계. 화면, 파일, 알림 등 다양한 형태가 있습니다.
SECTION 02

개발은 어떤 흐름으로 진행되는가

프로그램을 만드는 과정은 아래와 같은 흐름을 따릅니다.

단계내용
요구사항 확인무엇을 만들지 먼저 정합니다.
"엑셀 자료를 불러와 월간 보고서를 자동으로 만들고 싶다"처럼 목적과 필요한 결과물을 정리합니다.
설계입력자료, 처리 방식, 출력 형태를 미리 정합니다.
어떤 파일을 사용할지, 어떤 기준으로 계산할지, 결과를 어떤 화면이나 파일로 보여줄지 정합니다.
제작정리한 내용을 바탕으로 실제 프로그램을 만듭니다.
AI Agent를 활용하면 코드 작성과 파일 수정 과정의 많은 부분을 도움받을 수 있습니다.
테스트만든 프로그램이 의도한 대로 동작하는지 확인합니다.
오류가 나거나 결과가 다르면 원인을 찾아 수정합니다.
배포다른 사람도 사용할 수 있도록 실행 가능한 형태로 정리합니다.
웹 링크, 실행 파일, 공유 폴더 등 사용 방식에 맞게 제공합니다.
유지보수실제 사용 중 발견되는 오류를 고치고, 업무 기준이 바뀌면 기능을 수정하거나 보완합니다.
AI로 개발해도 사라지지 않는 것

AI가 코드를 대신 작성해준다고 해서 이 흐름 자체가 없어지는 것은 아닙니다.
무엇을 만들지 정하고, 결과를 검토하고, 방향을 판단하는 역할은 여전히 사람의 몫입니다.

SECTION 03

프로그래밍 언어와 자연어, 무엇이 다른가

사람끼리 쓰는 말(자연어)은 조금 모호해도 문맥으로 알아듣습니다. "대충 정리해줘"라고 해도 상대방은 상황에 맞게 판단해서 처리합니다.

하지만 컴퓨터에게 지시하는 프로그래밍 언어는 다릅니다. 정해진 문법과 순서를 정확히 지켜야만 컴퓨터가 이해합니다. 쉼표 하나, 괄호 하나가 빠져도 실행되지 않을 수 있습니다.

언어·도구설명
HTML화면 구조를 짜는 언어
CSS화면의 색상, 배치, 글꼴 같은 디자인을 입히는 언어
JavaScript화면에 클릭, 입력 같은 동작을 만들어주는 언어
Python데이터 처리나 자동화에 많이 쓰이는 언어
참고

"이런 언어들로 화면과 기능이 만들어진다" 정도만 알아두어도 충분합니다.

SECTION 04

라이브러리와 가상환경, 왜 필요한가

프로그램을 만들 때 필요한 기능을 매번 처음부터 코드로 작성하지는 않습니다. 이미 만들어져 있는 코드 묶음을 가져와 쓰는 경우가 많은데, 이것을 라이브러리라고 부릅니다.

비유
재료를 직접 재배하지 않는 이유
라이브러리는 이미 검증된 코드 부품, 가상환경은 프로젝트별로 분리된 재료 창고
요리할 때 밀가루를 직접 재배하고 반죽부터 만들지 않고, 이미 나와 있는 재료를 사다 쓰는 것처럼, 개발도 표 만들기·파일 변환·데이터 정리 같은 기능을 매번 새로 만들지 않고 이미 검증된 라이브러리를 가져다 씁니다.

라이브러리를 설치하면 그 코드가 컴퓨터 안에 저장됩니다. 진행하는 프로젝트가 하나뿐이라면 크게 문제되지 않지만, 여러 프로젝트를 동시에 진행하다 보면 프로젝트마다 필요한 라이브러리의 종류나 버전이 다를 수 있습니다.

상황설명
프로젝트가 1개일 때라이브러리를 컴퓨터에 바로 설치해도 크게 문제되지 않습니다.
여러 프로젝트를 동시에 진행할 때프로젝트마다 필요한 라이브러리 버전이 다를 수 있어, 한 곳에 섞어 설치하면 충돌이 날 수 있습니다.
그래서 프로젝트별로 독립된 작업 공간을 만들어 그 프로젝트에 필요한 라이브러리만 따로 설치합니다. 이 독립된 작업 공간을 가상환경(venv)이라고 합니다.
참고

3단계 실습 영상의 터미널 화면에서 낯선 명령어가 지나가는 순간이 있습니다. 대부분 방금 설명한 라이브러리를 설치하거나 가상환경을 준비하는 과정입니다.

AI Agent 방식 이해하기

SECTION 01

대화형 AI와 AI Agent, 무엇이 다른가

지금까지 사용해 온 Claude, ChatGPT, Gemini 같은 AI는 주로 사용자의 질문에 답변하거나, 문서 요약·초안 작성·아이디어 정리처럼 하나의 요청에 대한 결과를 제공하는 방식으로 활용되어 왔습니다.

AI Agent도 사용자가 원하는 목표를 설명하고 작업을 맡긴다는 점은 비슷합니다.

다만 차이는 답변을 제공하는 데서 끝나는지, 작업 흐름을 이어가며 결과물까지 만들어내는지에 있습니다.

예를 들어 여러 팀의 주간 실적을 취합해 요약 보고서로 정리하고 싶다면, 대화형 AI는 취합 방법과 표 구성을 제안할 수 있습니다. 이후 엑셀 파일을 열고, 내용을 옮기고, 문서를 편집하고, PDF로 저장하는 작업은 사용자가 직접 수행해야 합니다.

반면 AI Agent 방식은 사용자가 목표와 작업 폴더를 지정하면, 필요한 파일을 확인하고 데이터를 정리한 뒤 보고서 파일을 생성하고 PDF 형식으로 저장하는 과정까지 이어갈 수 있습니다.

예시
여러 팀 주간 실적, 요약 보고서로 정리하기

작업 폴더에 팀별 실적 엑셀 자료와 기존 보고서 양식이 있다고 가정해 보겠습니다.

대화형 AI에 요청하면
방법을 제안받고
나머지는 사람이 처리
  1. 엑셀 자료를 분석해 보고서 문구와 표 구성 방법을 제안받음
  2. 사람이 직접 엑셀과 문서를 열어 내용을 반영
  3. 사람이 최종적으로 PDF 파일로 저장
AI Agent에 요청하면
AI가 작업 흐름을 이어가며
결과물까지 생성
  1. 작업 폴더의 엑셀 자료와 보고서 양식을 확인
  2. 필요한 데이터를 정리하고 보고서 내용을 작성
  3. 보고서 파일을 생성하고 PDF 형식으로 저장
SECTION 02

승인 요청, 이런 뜻입니다

AI 개발 환경에서 AI Agent에게 작업을 시키다 보면 영어로 된 승인 팝업이 뜰 수 있습니다. 내용을 모른 채 무조건 Yes를 누르는 것은 위험할 수 있습니다. AI가 파일을 다루는 것을 넘어, 컴퓨터에 직접 명령을 내리거나 외부 자원을 가져오려는 순간일 수 있기 때문입니다.

실제로 자주 마주치는 승인 요청 네 가지를 하나씩 풀어서 설명드립니다. 용어가 낯설어 보여도, 각각 어떤 상황에서 왜 뜨는지만 알면 어렵지 않게 판단할 수 있습니다.

Do you want to install this package?
실제 의미

앞서 Chapter 01에서 배운 라이브러리를 새로 설치하려는 순간입니다. AI가 지금 만들고 있는 프로그램에 필요한 코드 부품을 컴퓨터로 가져오려는 것으로, 개발 과정에서 자연스럽게 일어나는 일입니다.

판단 기준

지금 요청한 작업과 관련 있는 이름의 패키지인지 정도만 확인하면 충분합니다. 대부분은 편하게 승인해도 되는 요청입니다.

Bash command — Do you want to proceed?
실제 의미

파일 하나를 만들거나 고치는 수준을 넘어, 컴퓨터에 직접 명령을 내리려는 순간입니다. 폴더를 정리하거나, 프로그램을 실행하거나, 설정을 확인하는 등 다양한 작업이 여기 해당합니다. 팝업에는 어떤 명령어를 실행하려는지와 함께 "왜 이 명령이 필요한지" 목적도 같이 표시됩니다.

판단 기준

명령어 자체가 낯설어 보여도 괜찮습니다. 함께 표시되는 목적 설명이 지금 내가 요청한 작업과 맞아떨어지는지만 확인하면 됩니다.

Do you want to edit this .env file?
실제 의미

비밀번호나 접속 키처럼 민감한 정보가 담길 수 있는 설정 파일을 건드리려는 순간입니다. 이런 파일은 다른 파일보다 더 조심스럽게 다뤄야 하기 때문에, 다른 요청은 자동으로 승인되도록 설정해두어도 이런 파일만큼은 예외적으로 매번 다시 확인을 요청합니다.

판단 기준

왜 이 파일을 수정해야 하는지 AI의 설명을 꼭 확인하세요. 이해되지 않는다면 그대로 승인하지 말고, 이유를 먼저 물어봐도 됩니다.

Do you want to push these changes?
실제 의미

내 컴퓨터에서 작업한 결과를 인터넷 저장소에 실제로 올려보내려는 순간입니다. 지금까지 고친 내용을 온라인에 반영해서, 다른 사람도 그 결과를 볼 수 있게 만드는 단계라고 이해하면 됩니다.

판단 기준

지금 작업이 정말 끝났는지, 올려도 되는 시점인지만 확인하면 됩니다.

참고

실제 승인 팝업에는 보통 세 가지 선택지가 함께 뜹니다. Yes(이번 요청만 승인), Yes, and don't ask again(비슷한 요청은 앞으로 묻지 않기), No(승인하지 않고 AI에게 다르게 요청하기)입니다. 판단이 서지 않을 때는 항상 세 번째를 선택해 AI에게 먼저 설명을 요청해도 괜찮습니다.

바이브코딩이란 무엇인가

SECTION 01

바이브코딩의 개념

바이브코딩(Vibe Coding)은 코드를 한 줄씩 직접 작성하는 대신, 만들고 싶은 기능을 자연어로 설명하고 AI와 함께 개발을 이어가는 방식을 말합니다.

Chapter 02에서 살펴본 AI Agent가 여러 단계를 이어가며 작업을 대신 처리하는 AI의 동작 방식이라면, 바이브코딩은 그 AI Agent에게 한 번 쓰고 끝나는 결과물이 아니라 계속 재사용할 수 있는 프로그램을 자연어로 설명해 만들어가는 개발 방식입니다.

"엑셀 파일을 업로드하면 자동으로 요약 보고서를 만들어주는 프로그램을 만들어줘"처럼 목적을 말로 전달하면, AI Agent가 필요한 파일을 만들고 수정하며, 실제로 동작하는 프로그램에 가까워지도록 작업을 이어갑니다.

SECTION 02

사람과 AI의 역할 분담

바이브코딩이라고 해서 사람이 할 일이 없어지는 것은 아닙니다. 오히려 무엇을 만들지 정하고 결과를 판단하는 역할이 더 중요해집니다.

사람
방향을 정하고
결과를 검토
  • 무엇을, 왜 만드는지 목적 정의
  • 업무 기준과 조건 설명
  • 결과물이 의도대로 나왔는지 검토
  • 수정이 필요한 방향 판단
AI
코드를 작성하고
결과를 이어감
  • 요청 내용을 바탕으로 코드 작성
  • 필요한 파일 수정
  • 오류 원인 분석
  • 실행 결과를 보고 개선안 제안
SECTION 03

바이브코딩에 대한 오해 정리

바이브코딩을 처음 접하면 "이제 개발을 몰라도 되는구나"라고 생각하기 쉽지만, 정확히는 다릅니다.

오해와 사실
몰라도 된다 vs 알수록 잘 시킨다
바이브코딩은 "개발 지식이 전혀 없어도 완벽하게 된다"는 뜻이 아니라, "개발 개념을 알고 있을수록 AI에게 더 정확하게 요청하고, 결과를 더 잘 판단할 수 있다"는 뜻에 가깝습니다.

학습 내용 확인 퀴즈

퀴즈를 모두 맞힌 후 교육 완료 버튼을 눌러야 해당 회차의 교육 이수가 인정됩니다.
